# System Design — 공개 요약

## 프로젝트의 질문

Gunfire는 ‘더 높은 등급 총을 언제 교체할까’보다 아래 질문을 중심에 둡니다.

```text
어떤 파츠가 지금 이 플랫폼의 약점을 보완하는가?
그 파츠를 얻기 위해 어느 지역의 위험을 감수할 것인가?
지금 수색을 계속할 가치가 있는가?
```

따라서 Weapon, Search, Inventory, 지역 Loot Identity와 귀환 판단은 독립 메뉴가 아니라 하나의 루프로 작동해야 합니다.

## 공간 문법

**2D/2.5D Side View + Broad Tactical Depth**가 최신 기준입니다. 구형 제한 레인식 표현은 사용하지 않습니다.

| 축 | 역할 |
| --- | --- |
| X | 주 진행, 거리 조절, 후퇴/전진 |
| Y | 사선 이탈, 엄폐 우회, 플랭킹, 포위 탈출 |

적의 공격은 위험 신호와 Commit 구간을 읽을 수 있어야 합니다. 플레이어의 기본 대응은 무적 판정이 아니라 공간을 사용한 이동입니다.

## 지역과 Loot Identity

지역은 위험 숫자만 다른 장소가 아닙니다. 각 장소는 원하는 무기/재료/방어 장비를 위해 방문할 이유를 만듭니다.

| 예시 지역 성격 | 기대되는 목적 |
| --- | --- |
| 치안 시설 | 권총·SMG·탄약·방탄 장비 |
| 공업 지대 | 기계 파츠·정밀 가공 소재·조율 도구 |
| 군사 시설 | AR·고관통 탄약·고 Precision Core Part |
| 연구 시설 | 연구 자료·특수 기술 자산 |

낮은 위험 지역에서도 고가치 발견은 가능하지만, 기대값과 접근 위험이 같은 방식으로 설계되지 않습니다.

## Base → Expedition → Base

```text
Base: 무기 조립 · 조율 · 준비
→ Expedition: 탐색 · 전투 · 수색 · Loot 선택
→ Return: 전리품 비교 · Gunsmith · 사격장 테스트 · Mastery
```

Base는 단순 보상 정산 화면이 아니라 다음 출정의 가설을 세우는 장소입니다. ‘더 좋은 M4를 찾아라’가 아니라 ‘이 플랫폼의 다음 조립 결정을 위해 무엇을 찾아야 하는가’를 만들고자 합니다.

## 현재 공개 경계

이 문서는 시스템 간 관계만 압축해 설명합니다. 상세 수치표, 내부 데이터 구조, 구현 파일, 원본 설계 정본과 운영 문서는 포함하지 않습니다.
